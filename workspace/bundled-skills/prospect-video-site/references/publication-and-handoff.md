# Preview publication and production handoff

## Metadata for this concept

Write a truthful page title and description and an intentional social-preview
image from usable assets. Keep visible name, location scope, contact details and
metadata consistent with the research. Omit private street addresses and
unsupported service areas. Preserve the required concept disclosure and
`noindex,nofollow,noarchive` on local and hosted previews.

A preview URL is not an official production URL. Do not invent a canonical URL,
create search-indexing or sitemap claims, or present the concept as an official
business site. Do not publish fabricated ratings, reviews, prices, coordinates,
hours, offers or profiles in structured data. The concept does not need business
JSON-LD merely to appear complete.

## Local preview and verification

Inspect the project instructions, scripts and existing server before starting a
preview. Use its supported command and an available port; reuse a matching
project server and never stop an unrelated process to claim a preferred port.
Wait for readiness and load the exact intended route, not merely the server root.
Verify assets, fonts, navigation, conversions, effects, console/network errors
and refresh behavior alongside the existing browser QA.

Report the actual command, URL, route, runtime/build status, observed results and
remaining blockers. Leave the server running only when that serves the current
workflow. Run applicable lint, typecheck, tests or build scripts if present;
for the static deliverable, the pipeline and browser checks remain required.

## Future production handoff, only when requested

This prospect workflow produces concepts. A separately authorized production
implementation must resolve the following before claiming launch readiness:

- Confirm the official public business identity and destination. Keep name,
  public address/service area, phone, hours and category consistent across copy,
  metadata and any structured data; retain private-address restrictions.
- Use unique human-readable titles/descriptions, descriptive headings and links,
  suitable social previews, and a canonical URL only when the official URL is
  known. Include location naturally without doorway pages or unsupported cities.
- When structured data is in scope, select a suitable type, include only
  verified visible facts, validate syntax and inspect the rendered result.
- Resolve media clearance, source attribution and business-provided privacy,
  terms, cancellation, refund or other policies applicable to the real service.
  Do not invent policy language or treat distinct trust claims as interchangeable.
- Treat a booking, ordering or map link as a verified link, not a configured
  integration. Test configured forms/integrations through their intended path,
  with authorized success/failure testing, validation, delivery and spam handling
  where applicable. Disclose analytics/tracking that is actually configured.
- For a redesign, inventory verified content and working integrations to retain;
  record scoped replacements and revalidation needs. For an audit, report
  evidence and findings without modifying the site unless changes are requested.

These are handoff requirements, not permission to enable indexing, submit forms,
configure third-party services, publish a production site or contact a business.
