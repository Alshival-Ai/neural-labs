# Neural Labs workflow

Work within the current project. When called by site-generator, continue that
project rather than starting a second orchestration run. This skill can also be
used directly for design, implementation or an audit.

A name and enough context to distinguish the business is enough to start. Use
business-research-and-media for official sources, verified facts and available
photos. Maps tools are optional; a missing Places listing or API key must not
block a supplied identity. Preserve unknowns rather than inventing business facts.

Honor explicit design choices; choose unspecified typography, composition and
motion to fit the business. Record the brief and visual direction before
substantial code. Use business-photo-direction.md and asset-policy.md for imagery,
and quality-contract.md for a reusable evidence handoff. A simple task need not
create a full pipeline of reports. Do not change existing project history.

Use the installed cinematic-interactions recipes for selected effects and
web-video-asset-preparation for video. Strong static design is valid. Inspect the
actual browser opening, full page, intermediate motion states and mobile layout.
Use the existing framework/build tools and runtime browser/preview capability.
Record observed defects, fixes and remaining gaps in VALIDATION.md. Use the
runtime's returned preview route; do not invent a public URL.

Keep research, source media and credentials outside public output. Deploy only
when requested, using `$deploy` and its hosting discovery. Do not change host
configuration, domains, schedules, models or notification settings. Report actual
asset origins and usage rights; never imply a missing integration works.
