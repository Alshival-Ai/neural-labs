# Neural Labs adapter

For a human-selected local business, use `$site-generator` for project identity,
research gates, staged implementation, QA and requested deployment. It calls this
skill for presentation; do not recurse into another orchestration run. If already
inside site-generator, continue its project. Read its workflow-contract and
act-production references. Only location-only scouting uses `$prospect-hunter`.

Name plus public address is enough to start. Verify the match, research official
sources and inspect Maps photos. Ask only if identity is genuinely ambiguous or
a missing answer prevents truthful work. Use AUTO for unspecified design/motion.
Preserve any explicit Tedy, GSAP, parallax, image style or output request.

For new builds record `experience.templateSkill: local-business-website-builder`,
`presentationProfile: evidence-led`, `motionPolicy: auto`, and `qualityVersion: 2`.
An explicit website-template-1 request retains that templateSkill identity while
using its compatibility adapter to this skill. A selected legacy cinematic
composition may retain cinematic-media-first and its extra geometry checks;
it is never the default. Do not change a completed project's history.

Before substantial code, produce the pipeline brief, DESIGN.md, STORYBOARD.md,
and BUSINESS-VISUAL-BRIEF.json using business-photo-direction.md. Plan asset roles
using asset-policy.md. Make one recognizable composition and at least one useful
design feature traceable to this business. A color swap is insufficient. Study
the RichBoys process via website-template-1/references/richboys-method.md only
when a process example helps; do not copy its visual identity across categories.

Use the actual available tools: `google_place_details` / `google_place_photo`,
browser/image inspection and configured `image_generate` (discover provider
availability). Never invent Codex imagegen tool access. The Models API's video
capability is not a still-image generator. Read the installed tool's own schema.
Do not require subagents; normal single-agent execution is supported.

Use `$cinematic-interactions` and the exact chosen recipe. Tedy is sticky image
choreography, not a low-fps video conversion. A DOM/GSAP effect does not need
video frames. For a continuous frame sequence, read its updated frame recipe and
this skill's motion-quality reference. Build a complete static page first; enable
sticky geometry only after the controller and required media are ready.

Use the existing framework or static HTML/CSS/JS. Publish only built `site/` with
local assets and external scripts compatible with the real publisher CSP. Keep
research/source media private. Run pipeline begin-build and complete-build; new
projects enforce version-2 direction/media gates. Read quality-contract.md for
the additional file schema. Never write a pass report by hand.

Inspect the actual browser opening, full page, intermediate motion states and
mobile page. Use the available Neural Labs browser tools; screenshots alone do
not prove smooth motion. Record defects and corrections in VALIDATION.md. For
frame scenes supply MOTION-QA.json with observed continuous-scroll results.

Use the runtime AGENTS.md preview format, never a localhost user link. Preserve
the requested output scope: hosted-preview uses `$deploy` and `$demo-pi` after
all gates; an explicit private/local preview stops there. No prospect outreach.
Do not change schedules, models, notification settings or production domains.
Report verified outcome, actual asset origins, observed QA and unresolved gaps.
