# Local SEO and Trust

Apply this reference to production-ready local-search work. SEO does not authorize research, account access, publishing, or external service configuration that the user did not request.

## Verified identity

Keep the official name, address or service area, phone, hours, and primary category consistent across visible content, metadata, and structured data. Do not add a street address for a service-area business when it should remain private.

## Page metadata

- Write a unique, human title and description that match the actual page and location scope.
- Set a canonical URL only when the production URL is known.
- Provide intentional Open Graph and social-preview metadata using an approved image.
- Use one clear page topic, descriptive headings, meaningful link text, and useful alt text.
- Include location terms naturally where they help users; do not create doorway pages or lists of unsupported cities.

## Structured data

Choose the closest supported business subtype and include only verified, visible facts. Keep JSON-LD consistent with the page. Do not fabricate `aggregateRating`, `review`, `priceRange`, geo coordinates, opening hours, menus, offers, or social profiles.

Validate structured data syntax and inspect rendered metadata. Structured data is a machine-readable representation of evidence, not a place to add claims that are absent from the page.

## Trust and contact

- Attribute reviews or testimonials and confirm permission or source suitability.
- Link maps and directions to the correct verified destination.
- Distinguish credentials, memberships, awards, guarantees, and years in business; they are not interchangeable.
- Make privacy, terms, accessibility, refund, cancellation, and service policies available when the business and integrations require them.
- For analytics, forms, booking, ordering, chat, or tracking, disclose what is configured and test the actual production path before calling it complete.
