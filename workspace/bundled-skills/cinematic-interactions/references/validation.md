# Validate the Cinematic Skill

Validate the actual claim being made. An instruction package, a representative implementation, and an agent's ability to follow the package are different subjects.

## Package checks

Run the skill-creator validator when available. Check that every referenced file resolves, each catalog recipe exists, the source map covers all ten article entries, and callers reach the shared catalog. Compare updates against the installed version to preserve environment-specific fixes and selection policies. For a remote sync, compare hashes of the installed files with the reviewed package and confirm the application's skill loader can list and read it.

## Browser mechanics

Implement selected recipes in an isolated local fixture using the real animation library. Use observable DOM state and rendered output rather than asserting that the implementation contains expected strings. Cover:

- start, midpoint, endpoint, reverse travel, rapid movement, and mid-scroll reload;
- multiple instances or adjacent scenes, scoped cleanup, and unmount/remount;
- responsive changes, mobile/touch interaction or fallback, keyboard focus visibility, and accessible reading order;
- reduced motion at load and while running, with no stale transforms, hidden content, or spacer height;
- content fitting without overflow as well as overflowing; first and last gallery items must become visible;
- ticker stillness and seam continuity, image crop/coverage, and unavailable media where applicable.

Inspect screenshots and normal-speed movement. Synthetic DOM graphics can isolate transform mechanics; they cannot validate real video seeking, cutout quality, image payloads, low-end device performance, or production art direction. Record these limits rather than marking them passed.

## Skill-following evaluation

For a stronger evaluation, use a fresh agent when delegation is authorized, or a separate clean task explicitly requested by the user. Supply the skill path, realistic request, and raw assets without the intended solution. Keep work in a disposable project and avoid external publication or paid asset generation unless authorized.

| Request | Behavior to evaluate |
| --- | --- |
| Add scroll text emphasis to an existing page using its supplied copy | Select only the text recipe; preserve the framework; do not require video or the full effect questionnaire |
| Build a local-business concept without an effect preference | Follow that builder's selection policy, expose canonical names, and wait only when a choice is required |
| Continue a Neura build whose selected template already specifies AUTO | Preserve AUTO and record the actual choice; do not introduce a new questionnaire or another presentation director |
| Add a horizontal project gallery with different card widths | Measure the real clipping viewport and total overflow; expose every item on mobile and keyboard navigation |
| Add layered parallax with only one flat source image | Identify the missing aligned layers, retain a truthful static fallback, and do not invent ready assets |
| Compose an explicitly requested text reveal and spiral gallery | Load the selected recipes, keep independent progress and cleanup, and verify the complete page traversal |

Review actual outputs against the request and browser acceptance checks. Record routing, instruction adherence, visual quality, and runtime correctness separately. Fix demonstrated skill ambiguities, then rerun only the affected scenarios. Do not claim an independent evaluation when the same author wrote both the recipe and the fixture.
